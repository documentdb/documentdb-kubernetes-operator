## Boundary and protocol checks

- Generated messages were inspected through the official MCP client while
  concurrent ingestion continued.
- A real pinned Collector delivered both signals, including its default gzip
  compression and resource enrichment.
- Oversized uncompressed and compressed requests were rejected and counted.
- Old-protocol JSON-RPC batches were rejected before SDK dispatch.
- Unknown diagnostic names were pseudonymized; filtered attributes, events,
  and status messages did not leak into tool output.
- Validated, bounded exemplar trace/span associations were preserved, with
  explicit omission reporting.
- Histogram consistency, exact integer deltas, reset epochs, partial delta

  covered by focused tests.
- An unlabelled peer could not establish an OTLP connection to the tool while
  the actual sidecar exports worked. The tool's MCP port was also unreachable

  or encryption guarantee.

## Blocked gateway-pool case

No gateway-pool diagnosis is claimed.

The pinned source's `PgConfiguration::max_connections` reads PostgreSQL's
`max_connections`. `PgPoolSettings::adjusted_max_connections` subtracts the
system budget and applies a floor at that budget. The test server reported
`max_connections=300`; no matching `systemConnectionBudget` setting was
returned by the inspected `pg_settings` query.

This did not establish an independent, safe small gateway-pool cap. The
experiment did not lower server connection capacity or fabricate client-side
queuing as an equivalent fault. A documented, validated control and occupancy
or queue evidence are needed before running this case. An acquisition span
alone can include connection creation/recycling, not just queue waiting.

## Implementation findings

The real Collector exposed missing gzip support that direct generated
exports did not reveal. Independent review then identified legacy MCP batch
fan-out, unsafe diagnostic names, discarded exemplars, inconsistent histogram
sum differences, and stale selected gauges hidden by other metrics. All five
were corrected with regression cases and rerun checks.

The initial independent observation attempt also revealed a harness handoff
issue: Ginkgo indented neutral metadata lines, while the observer matched only
unindented prefixes. The observer correctly declined to invent trial
boundaries. The repeat handoff strips leading whitespace rather than exposing
fault labels.

### Rehearsal fixes and negative checks

- A clean environment exposed the missing Helm repository prerequisite.
  `up` now registers the required chart repository in a private Helm
  configuration and cache, rather than assuming global setup.
- The installed CLI rejected the initial launcher argument shape. Explicit
  option assignments and a non-option prompt prefix fixed the invocation.
  The failed attempt did not release the readiness gate or start workload
  setup.
- Independent review found that interrupting host-side `docker exec` alone
  left setup running in the devcontainer. The lifecycle supervisor now
  verifies the recorded PID, process start time, group, and session before
  signalling that owned process tree. A non-destructive regression proves
  cancellation propagation and nonzero interrupt status. The follow-up
  review found no significant issues.
- `down` was attempted during an active live run and correctly refused to
  acquire its lifecycle lock. The owned cluster stayed running.
- Regression tests reject stale or foreign readiness, changed captures,
  health gauges as request evidence, boundary-crossing intervals, old
  traces, trace lists as detail, retrospective receipts, replaced cluster
  nodes, changed Docker daemons, and symlinked lifecycle state.
- Full module build, race tests, and vet; E2E compilation and vet; operator
  build and routing tests; and the real pinned Collector check passed.
  The Collector check used the anonymous Docker configuration after an
  attempt using the default Docker configuration failed to become responsive.

The final `down` removed the owned cluster, kubeconfig, anonymous Docker/Helm
configuration, observer state, and in-memory capture. A subsequent check
found no kind clusters or running experiment containers. Local build images
and ignored compact proof/timestamped observer output remain for inspection;
no raw telemetry archive or images were published.

This establishes a repeatable developer demo of live reads and interpretation,
not guaranteed future model output or diagnosis accuracy. Gateway-pool
contention, CPU correlation, and the instrumentation gaps above remain
explicit follow-ups.
